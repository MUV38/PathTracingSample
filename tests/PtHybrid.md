# ReSTIR PTの1バウンスhybrid shift

`--restir-pt hybrid` は前フレームの生候補1本を使います。粗さ0.2未満の一次面で選ばれた鏡面またはGGX反射を、保存したBSDF乱数3つから再生します。再生先が元と同じ三角形かつ粗さ0.2以上なら、3番目の平坦なLambert頂点へ再接続します。再接続には表裏と可視性の検査を含めます。最初の2頂点の直接光と、接続先自体の発光は通常PTの寄与です。

提案は一次面の一様乱数と、再生先のBSDFでサンプルされた接続頂点の面積で定義します。乱数は両方向のシフトで同じ値を使います。接続で立体角PDFにヤコビアン `cos(接続先)/距離²` を掛け、再生区間のthroughputと再生先BSDFから寄与を計算します。シフトに失敗した方向のPDFはゼロです。光が得られなかったサンプルも、一次面の履歴判定に合格すれば提案として扱います。重みには既存のbalance MISを使います。

`--gi-view history` はシアンで選択された履歴、緑で再接続可能だった履歴、紫で再接続に使える候補がなかった履歴を表示します。赤は一次面の不一致、橙は履歴無効、黒は対象外の一次面です。通常の出力に切り替えると間接光を含む総照明を表示します。

```powershell
.\tests\RunPtHybrid.ps1 -Configuration Debug
.\tests\RunPtHybrid.ps1 -Configuration Release
```

鏡面と低粗さGGXのシーンで、通常PT、履歴なし、hybridのRGB平均を比較します。カメラの低速パンでは隣接フレーム間の画面上の輝度差を測ります。この指標には視点移動による画像の変化も含まれます。カメラカットでは履歴破棄と翌フレームの再開を検査します。同一GPU時間の比較は約1000 msで撮影し、通常PTの2048サンプルを参照にします。計測中は他の描画テストを並列実行せず、結果は `build/checks/pt-hybrid-<構成>/` に保存します。

RTX 3060 TiでDebug／Releaseともに、鏡面とGGXのRGB平均、履歴選択、カメラカットを確認しました。Releaseの鏡面シーンの平均輝度は通常PTが0.331191、hybridが0.331215でした。

| Releaseのモード | GPU時間 | サンプル数 | 輝度MSE |
| --- | ---: | ---: | ---: |
| 通常PT | 1016.0 ms | 98 | 0.003547 |
| hybrid | 1024.9 ms | 81 | 0.004245 |

低速パン時のフレーム差MSEは通常PTで0.01014、履歴なしのhybridで0.67091、履歴ありで0.66776でした。通常PTはカメラ移動に伴う蓄積リセット時に乱数系列を繰り返し、hybridはフレームごとに系列を進めます。履歴の効果を見る際は、乱数系列が揃うhybrid同士を比較してください。

## 黒い候補の省略と計測

反射放射輝度のRGBがすべてゼロなら、その候補自身の再生と可視性チェックを省略します。別候補のbalance MIS分母に含まれる提案PDFは、黒い候補しか生成しなかった提案についても評価します。`--hybrid-unoptimized` で省略前と比較できます。履歴ビューは黒い履歴候補の接続可否も表示するため、その候補への再生を維持します。

`--gi-view hybrid-cost` の赤は再生レイ数、緑は再接続の可視性チェック呼び出し数、青は履歴候補の採用数です。赤・緑を `2 × spp`、青を `spp` で割って表示します。可視性チェックは矩形光源で遮られた場合にも数えるため、緑はRayQueryの実行回数と区別します。PIXでDispatchRaysとマーカーを確認し、GPU時間はアプリ内のタイムスタンプ、個別の処理量は診断画像から集計します。今回の環境ではPIXのタイミングカウンター取得にWindowsの追加権限が必要でした。

```powershell
.\tests\RunPtHybrid.ps1 -Configuration Release -CompareCost
.\tests\RunPixCapture.ps1 -Configuration Release -HybridCost
```

Debugにも同じ手順を適用します。`build/checks/pt-hybrid-cost-<構成>/work.csv` は1280×720の右側35%における1sppの処理量です。静止画像とカメラ移動32フレームのRGBを同じ乱数系列で比較します。`budget.csv` は鏡面とGGXの通常PT・省略前・省略後を各約1000 GPU msで比較します。GPU時間の計測は他の描画テストと順番に実行してください。

RTX 3060 Tiでは、Debug／Releaseともに、検査範囲内でRGBの差はゼロでした。履歴採用は鏡面で6649画素、GGXで6357画素で、省略前後で一致しました。

| シーン | 再生レイ数 | 可視性チェック数 |
| --- | ---: | ---: |
| 鏡面 | 20,412 → 15,282 | 20,283 → 15,176 |
| GGX | 19,349 → 14,489 | 19,253 → 14,406 |
| 黒い候補のみ | 20,491 → 0 | 20,373 → 0 |

ReleaseのGPU時間中央値は、最初の10フレームを除くと鏡面で12.67 → 12.36 ms、GGXで12.99 → 12.67 msでした。同じ約1000 GPU msで蓄積した総照明の輝度MSEは次のとおりです。

| シーン | 通常PT | 省略前 | 省略後 |
| --- | ---: | ---: | ---: |
| 鏡面 | 0.003540 | 0.004282 | 0.004161 |
| GGX | 0.005484 | 0.006809 | 0.006664 |

## 再接続品質の診断

`--gi-view hybrid-quality` または ImGui の `Hybrid quality` は、各画素の最初のサンプルで、前フレームの候補を現在の一次面へ移した結果を表示します。赤は面積ヤコビアンを含む寄与の分子の輝度、緑は面積PDFについて、現在の値を保存時の値で割った比です。寄与にはMISの重みを含めません。赤と緑は `0.5 + log2(比) / 16` を0～1に収めた値で、両端はおよそ1/256倍以下と256倍以上です。比の分布は接続に成功し、比を計算できた候補を対象にします。

| 青の8ビット値 | 状態 |
| ---: | --- |
| 0 | 一次面が対象外、または履歴無効 |
| 51 | 一次面の再投影・一致判定で棄却 |
| 102 | 一次面は一致したが、再利用できる非ゼロの履歴候補がない |
| 153 | 履歴候補を再生・再接続できない |
| 204 | 再接続に成功し、比を計算できた |
| 255 | 再接続に成功したが、比は未定義 |

```powershell
.\tests\RunPtHybrid.ps1 -Configuration Debug -Quality
.\tests\RunPtHybrid.ps1 -Configuration Release -Quality
```

鏡面、低粗さGGX、遮蔽板のある鏡面を撮影します。遮蔽板のシーンでは低速パンとカメラカットも撮影します。`build/checks/pt-hybrid-quality-<構成>/quality.csv` に画面右側35%の状態別画素数と2倍範囲外の件数を、`ratios.csv` に8ビット値別の分布を保存します。接続成功率の分母は、非ゼロの履歴候補に対する接続試行数です。

RTX 3060 Tiでは両構成で同じ集計になりました。静止3シーンの合計では、21,280件の接続試行のうち21,128件が成功し、寄与の比が約0.5～2倍の範囲を外れたのは115件でした。遮蔽板の低速パン8フレームでは、48,221件のうち47,750件が成功し、そのうち339件が範囲外でした。カメラカットのフレームは全画素が履歴無効または対象外でした。診断を切った鏡面シーンのRGBは、前段の保存画像と検査範囲内で一致しました。

## 時間reservoir

`--restir-pt reservoir` は1バウンスhybridの経路を時間方向に繰り返し再選択します。保存するのは最初のsppの選択経路、ランダムな寄与重み、信頼度です。経路の始点情報は現在の一次面へ更新します。初期の重みは面積PDFの逆数です。再接続時は乱数と接続先の面積座標を保つため、この領域間のシフトのヤコビアンは1です。再生先で評価する面積PDFは接続可能性の判定に使います。

現在と履歴の両方で生成できる経路の配分は `1/(1+α)` と `α/(1+α)` です。現在だけが生成できる経路には現在側の寄与をすべて割り当てます。`α` は信頼度上限から1を引いた値で履歴信頼度を制限し、現在のsppで割った値です。配分した寄与の輝度で選択し、選択確率の逆数を掛けた重みを次のフレームへ渡します。信頼度は選択結果にかかわらず `1+α` です。これは [GRIS](https://research.nvidia.com/publication/2022-07_generalized-resampled-importance-sampling-foundations-restir) の寄与重みを使う限定的な時間モードです。カメラ再投影と相関を含む実装全体の収束保証はこの検証の範囲外です。

`--gi-view reservoir` は最初のsppの信頼度を赤、選ばれた経路の経過フレーム数を緑、履歴選択を青に表示します。新しい経路は緑0から始まり、履歴から選ばれるたびに1増えます。緑は32フレームで最大になります。カメラカット後に有効な一次面は信頼度1から再開します。黒い経路の試行も信頼度には数えます。

```powershell
.\tests\RunPtHybrid.ps1 -Configuration Debug -Reservoir
.\tests\RunPtHybrid.ps1 -Configuration Release -Reservoir
```

結果は `build/checks/pt-reservoir-<構成>/` に保存します。鏡面とGGXのRGB平均を2048サンプルの通常PTと比較し、履歴の蓄積・カメラカット・黒い経路を診断画像で確認します。鏡面シーンでは履歴なし・生候補1本・reservoirを同じ約1000 GPU msで比較します。

RTX 3060 TiのReleaseでは、鏡面シーンの平均輝度は通常PTが0.331184、reservoirが0.331190でした。同じGPU時間での総照明の誤差は、次の測定では履歴なしが最小でした。

| モード | GPU時間 | サンプル数 | 輝度MSE |
| --- | ---: | ---: | ---: |
| 履歴なし | 1017.2 ms | 82 | 0.004155 |
| 生候補1本 | 1019.1 ms | 77 | 0.004445 |
| 時間reservoir | 1019.9 ms | 75 | 0.004556 |

### 間接光の誤差とGPU時間の比較

`--pt-reservoir-confidence 2..8` は履歴信頼度の上限を指定します。既定は8です。信頼度の診断画像は引き続き8を赤の最大値として表示するので、上限2・4・8の違いを同じ色スケールで読めます。

```powershell
.\tests\RunPtHybrid.ps1 -Configuration Debug -EvaluateReservoir
.\tests\RunPtHybrid.ps1 -Configuration Release -EvaluateReservoir
```

鏡面と低粗さGGXで、履歴なし、生候補1本、reservoirの上限2・4・8を比較します。比較する5方式は1sppで、開始時の乱数系列を揃えます。`--gi-view diffuse` はここでは再接続の対象になる間接光を表示します。固定サンプル数ではこの間接光を、約1000 GPU msでは間接光と総照明をそれぞれ比較します。

各成分の参照は履歴なしの2048サンプルです。輝度MSEは画面右側35%を4画素間隔で取り、PNGから復元した輝度で計算します。参照輝度が0.0003未満の画素は集計から外します。結果と撮影画像は `build/checks/pt-reservoir-eval-<構成>/` に保存します。構成を順番に実行してGPU時間を測ります。

RTX 3060 TiのReleaseで得た129サンプル時の間接光の輝度MSEです。Debugでも同じ順位でした。

| 上限4 | 1.3071e-4 | 1.1028e-4 |
| 上限8 | 1.4920e-4 | 1.2260e-4 |

#### 固定GPU時間の反復計測

```powershell
.\tests\RunPtHybrid.ps1 -Configuration Release -EvaluateReservoir -RepeatBudget
```

各シーン・成分の時間予算テストを5ラウンド実行します。方式の順番を毎ラウンド2つずつずらし、各方式が1番目から5番目までを一度ずつ担当します。参照画像はシーン・成分ごとに共有し、固定サンプル数の比較は一度だけ行います。GPUの計測中は他の描画テストを並列実行しないでください。

`build/checks/pt-reservoir-budget-repeats-<構成>/evaluation.csv` に各回の実行順、GPU時間、サンプル数、輝度MSEを保存します。`budget-summary.csv` には同じラウンドの履歴なしを基準としたMSE比の中央値・最小値・最大値と、比が1未満だった回数、サンプル数の中央値と範囲を出力します。乱数系列は各回で共通なので、範囲はGPU時間予算内に描けたサンプル数の変動を含む実測値です。

RTX 3060 TiのReleaseでのMSE比の中央値です。括弧内は履歴なしよりMSEが小さかった回数です。

| 鏡面・総照明 | 1.120 (1/5) | 1.047 (1/5) | 1.129 (0/5) | 1.211 (0/5) |

| 低粗さGGX・総照明 | 0.994 (3/5) | 0.950 (3/5) | 1.128 (1/5) | 1.004 (1/5) |

今回の2シーンでは、上限を2まで下げても、再利用対象の間接光の誤差は全ラウンドで増えました。低粗さGGXの総照明では上限2の中央値が約5%改善しましたが、比の範囲は0.93〜1.21で、ラウンドごとに優劣が入れ替わりました。

### フレーム間の相関と周期更新

`--pt-refresh-period 0..256` は時間reservoirが履歴を使わず、現在の候補から作り直す周期をフレーム数で指定します。既定値0は周期更新を無効にします。更新の位相は画素座標から決めます。1を指定すると毎フレーム更新します。

```powershell
.\tests\RunPtHybrid.ps1 -Configuration Release -EvaluateRefresh
```

鏡面と低粗さGGXで履歴なし、上限2・8、上限8に周期4・8を加えた方式を比較します。1 sppで32サンプルまで描画してから、蓄積前の間接光を64フレーム連続保存します。画素ごとの64フレーム平均を引いた輝度を使い、同じ画素の1・2・4・8フレーム差の正規化相関を測ります。参照画像は集計対象のマスクに使用します。有限長の系列から平均を引くため、履歴なしでも相関は厳密に0にはなりません。

間接光を固定サンプル数で、間接光と総照明を約1000 GPU msで比較します。符号付き平均輝度誤差は画面右側35%の画素から求めます。出力先は `build/checks/pt-refresh-<構成>/` で、相関は `temporal-correlation.csv`、固定サンプル数と時間予算の比較は `evaluation.csv` に保存します。時間予算を反復するには `-RepeatBudget` を追加します。

RTX 3060 TiのReleaseで測った相関です。

| 方式 | 鏡面・1フレーム差 | 鏡面・4フレーム差 | 低粗さGGX・1フレーム差 | 低粗さGGX・4フレーム差 |
| --- | ---: | ---: | ---: | ---: |
| 履歴なし | −0.014 | −0.016 | −0.014 | −0.017 |
| 上限2 | 0.468 | 0.013 | 0.469 | 0.011 |
| 上限8 | 0.749 | 0.373 | 0.751 | 0.381 |
| 周期4 | 0.486 | −0.053 | 0.489 | −0.054 |
| 周期8 | 0.587 | 0.161 | 0.588 | 0.158 |

同じRelease計測で、上限8の周期更新なしを1とした間接光の輝度MSE比です。

| シーン・条件 | 周期4 | 周期8 |
| --- | ---: | ---: |
| 鏡面・129サンプル | 1.219 | 1.348 |
| 低粗さGGX・129サンプル | 1.237 | 1.434 |
| 鏡面・約1000 GPU ms | 1.446 | 1.500 |
| 低粗さGGX・約1000 GPU ms | 0.917 | 1.400 |

周期更新で相関は下がりましたが、129サンプルに揃えると両周期・両シーンでMSEが増えました。固定GPU時間では履歴なしと上限2のうち、少なくとも一方のMSEが両周期より小さくなりました。これは間接光と総照明の両方で共通です。周期更新の129サンプル時の符号付き平均輝度誤差は +1.6e-5〜+3.9e-5 でした。輝度誤差の比較は単一シード、時間予算は各方式1回の計測です。
