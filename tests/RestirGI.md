# 拡散GIの初期候補と1フレーム時間再利用

`ReSTIR GI` パネル、または `--restir-gi off|candidates|temporal` で選びます。既定はoffです。

- off：通常PT。
- candidates：初期候補の生成と、再利用なしの再構成。
- temporal：現在の候補と、再投影先の前フレームの生候補1つをRISで統合。

```powershell
.\build\x64\Debug\UsdKitchen\UsdKitchen.exe --model assets/PreviewRoom.ptscene --specular 0 --restir-gi temporal
.\build\x64\Debug\UsdKitchen\UsdKitchen.exe --restir-gi temporal --no-gi-history
.\tests\RunRestirGI.ps1 -Configuration Debug
.\tests\RunGiTemporal.ps1 -Configuration Debug
```

Releaseも同じ手順で確認してください。SDKの追加取得は不要です。
`--specular 0` は検証用に全マテリアルのspecularを0へ上書きする既存オプションです。
Kitchen Setなどの元のPBR設定を維持したい場合は指定しないでください。

## 対象と経路の分離

一次面はroughness 0.2以上の有限な拡散成分を持つ面です。
時間再利用する二次面は **metallic=0、specular=0、補間法線が幾何法線と一致するLambert面** に限定します。
視線角による幾何法線への退避より前の法線を使い、差の二乗を1e-8未満とします。
Lambert面の反射放射輝度は、同じ向きの面上では見る方向に依存しません。
鏡面、GGX、滑らかな法線の二次面は通常PTへ残し、方向依存の輝度をそのまま使い回しません。
一般的なspecular=0.5のモデルでは再利用できる範囲が小さいか、なくなる場合があります。

candidatesは一次面の拡散間接成分全体、temporalはそのうちLambert二次面へ接続する成分を担当します。
担当成分を元のPTから差し引いてから再評価するため、二重加算しません。
二次面自体の発光、一次面から直接見えた矩形光源・IBLは既存の直接光とMISへ残します。
二次面で反射したNEE、その先の反射・発光・IBLは候補の輝度へ含めます。
静的シーン専用で、変形・物体移動の再投影には対応しません。

## 再投影とMIS

既存のGGX VNDF＋cosine混合の方向と、混合全体の立体角PDFを保存します。
Russian Rouletteの生存判定・補正も元の経路と共有します。生成用の追加レイや乱数は使いません。
時間再利用では遮蔽確認用RayQueryと、PT乱数を乱さないRIS選択用の独立乱数を追加します。

現在の一次位置を前フレームのview-projectionへ再投影し、三角形・マテリアル番号、法線、色、位置を確認します。
法線の内積は0.98超、色の差は各成分0.05未満、位置の差は約2画素分またはshadow biasの4倍以内です。
両方の一次面から各二次候補へ接続し、BRDFの半球とシーン／矩形光源の遮蔽を確認します。
二次面の表裏は別の領域として扱います。

両提案のPDFと積分項を世界空間の面積measureへ変換します。
立体角からの変換係数は `J=abs(dot(N_secondary,-direction))/distance²` です。
現在の提案をq0、過去をq1、現在のsppをS、λ=1/Sとすると、2つの寄与は次のとおりです。

- 新候補：`F(y0)/(q0(y0)+λq1(y0))`
- 過去候補：`λF(y1)/(q0(y1)+λq1(y1))`

この2項を線形輝度でRIS選択し、選択確率の逆数で補正します。Jを重みへ二重適用しません。
過去の同じ生候補を各sppで参照するため、λで過去1サンプルの過大な重み付けを避けます。
過去の実サンプルがMiss・黒・対象外でも、過去の一次面が有効ならq1を正規化から除きません。
再利用の可否をサンプルの明るさで決めると偏りが生じるためです。
遮蔽時は該当する積分項・提案PDFを0とします。レイバイアスと有限精度の微小な幾何差は既存PTと同じ扱いです。

## 履歴とメモリ

保存するのは **再選択前の最初のsppの生候補** です。
選択結果を翌フレームへ戻す再帰的reservoir蓄積と、空間再利用は未実装です。
時間相関も増えるため、長時間蓄積の収束が必ず速くなるとは限りません。

初期候補96バイトに一次面の法線・幾何法線・色・視線・材質番号・有効性などを加え、1要素160バイトです。
現在バッファは1280×720で約140.6MiB、1920×1080で約316.4MiBです。
通常の時間再利用では過去分も確保し、それぞれ計281.3MiB、632.8MiBになります。
生成無効時と不要な履歴は1要素です。sppを増やしても保存バッファは増えません。

リサイズ、モデル／マテリアル／照明・積分設定の変更、Reset accumulation、カメラカットで履歴を破棄します。
カットは1フレームで注視距離の半分を超える移動、または45度を超える視線変更です。
通常の移動は再投影で処理し、temporalのPT乱数は蓄積リセットに依存しないフレーム番号を使います。
RRガイド専用表示、DI診断、GI固定ガイドでは時間再利用を停止し、照明へ戻ると新しい履歴を作ります。

## 診断表示

`--gi-view` または `GI view` で選びます。output以外は生成を有効にし、RRを迂回します。

| 値 | 内容 |
| --- | --- |
| output | 通常の総照明。RRとも併用可能 |
| diffuse | そのモードが担当する拡散間接光。蓄積あり |
| remainder | 担当する新候補の寄与を除いたPT成分 |
| radiance | 現在の二次候補の反射放射輝度 |
| normal / pdf / valid | 現在の二次法線／立体角と面積PDF／有効性。固定サンプル、再利用なし |
| error | 新候補の再構成誤差×1000。再利用後の値との差ではない |
| history | 緑：過去の提案を受理、青：過去候補を選択、赤：再投影／面の一致で棄却、橙：履歴無効、黒：一次面が対象外 |
| diffuse-noisy | 蓄積しない1フレームの拡散GI |

historyはtemporalを自動選択し、一次レイを画素中心にします。
`--no-gi-history` または `Reuse previous GI candidate` をオフにすると、temporalの対象範囲を維持したまま新候補だけで評価できます。
固定ガイドとerrorでは履歴を読みません。DIのG-buffer表示はGI表示に優先し、Meshlet colorsではGIを無効にします。
validは初期候補の有効性であり、時間再利用の可否ではありません。実際の過去候補の選択はhistoryの青で確認します。

## 検証

`RunRestirGI.ps1` は従来の初期候補17ケース、通常PT／DI／RR／発光シーンの同一乱数比較と成分の加算一致を確認します。
`RunGiTemporal.ps1` は次を確認します。

- 再利用有無の総照明・拡散GIの平均値、DI・RR併用、黒・金属・非Lambert面のフォールバック、GPU履歴表示。
- 色付き光源＋GGXと拡散を持つ一次面＋Lambert二次面の自作フィクスチャでのRGB平均値。
- 高サンプル参照に対し、1spp・蓄積なしGIを16フレーム撮影し、輝度MSEが減ること。
- 支持領域が異なる2提案、nullサンプル、多sppの重み、RISのGPU数値チェック。
- 低速パン、カット、リセット、光源・マテリアル変更、リサイズ中の履歴破棄／再開。

`--gi-validation <CSV>` は検証専用の明示オプションで、上記の操作をフレーム番号で実行します。通常起動では動きません。
CSVのhistoryはCPUの履歴利用許可フラグであり、画素別の使用量ではありません。
テストではCPUの破棄／再開に加え、GPUのhistory画像が破棄時に橙になることも確認します。
保存先は `build/checks/gi-temporal-<構成>/` です。PNGも開いて確認してください。
これは静的シーンのスモークテストで、全シーンでの厳密な不偏性・NaN不存在・性能向上を保証するものではありません。
自動シーケンスと手動の入力操作は区別してください。

実装時はDebug / Releaseで専用テストとGI候補・DI・白色環境・RR・PIXの回帰を実行し、保存画像も確認しました。
検証シーンの1spp輝度MSEは両構成とも0.0293671から0.0147473へ約49.8%減少しました。
Kitchen Setの元のPBR設定とspecular=0設定でも、両構成の描画を確認しています。手動のUI・キー／マウス操作は未確認です。

設計の背景は [NVIDIA RTXDIの説明](https://github.com/NVIDIA-RTX/RTXDI/blob/main/Doc/RestirGI.md) も参照しています。SDK自体は組み込んでいません。
