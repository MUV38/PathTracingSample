# Russian Roulette

UsdKitchenは既定でRussian Roulette（RR）を使います。`--no-russian-roulette` またはImGuiの `Russian roulette (after 3 bounces)` で無効にできます。切り替えは既存の定数比較により蓄積をリセットします。

現在の頂点で発光・直接照明・NEEを加え、次のBSDFをサンプリングしてスループットを更新した後、3反射目以降の継続を抽選します。
生存確率はRGB最大成分を0.05～1に制限した値です。生存した経路のスループットをこの確率で割ります。最大成分が1以上なら常に継続し、ゼロなら即終了します。
RGBの平均ではなく最大成分を使うため、飽和した色の強い成分を過剰に終了させません。現在のレンダラーは反射のみです。

共通の `samples/UsdKitchen/RussianRoulette.hlsli` を実描画とGPU数値テストで使います。
BSDFの方向PDFや各光源とのMIS重みにはRR確率を掛けず、独立の継続抽選をスループットで補正します。現在の頂点で得た寄与は消しません。
既存の `--bounces` は引き続きハード上限です。RRは同じ上限で計算量を減らす方式で、上限による打ち切り誤差を取り除くものではありません。
また、同じサンプル数では分散が増える場合があります。実シーンでの速度・同時間当たりの誤差改善は別途計測が必要です。

参考: [PBRT: A Better Path Tracer](https://pbr-book.org/4ed/Light_Transport_I_Surface_Reflection/A_Better_Path_Tracer)。

## 実行

Visual Studio 2026でルートのソリューションをDebug / Releaseビルド後、リポジトリ直下から実行します。

```powershell
.\tests\RunRussianRoulette.ps1 -Configuration Debug
.\tests\RunRussianRoulette.ps1 -Configuration Release
```

出力はGit管理外の `build/checks/roulette-<構成>/`（`-OutputDirectory` で変更可能）です。
WhiteFurnaceTestsの既存4,128条件に続き、14条件のRR数値検証を実行します。数値テストのみなら `WhiteFurnaceTests.exe <出力先>`、WARPなら末尾に `--warp` を付けます。

RR数値検証では、8頂点にそれぞれ発光1があり、各反射でRGB一定の減衰を受ける経路を131,072本サンプリングします。
各頂点の寄与を継続抽選より先に加えます。解析解 `1 + a + ... + a^7` およびRRなしの平均値との誤差が `0.0005 + 6 × 標準誤差` 以内か検査します。RR有無の比較では両者の標準誤差の二乗和平方根を使います。
白、灰、色付きの減衰、最大成分1の飽和色、1を超える成分、非常に小さい減衰、完全な吸収の7条件をRR有無で検査します。
開始反射回数、生存確率の下限・上限、ゼロ経路、抽選境界、生存時の重みも検査します。
灰色などの吸収経路では平均訪問頂点数が5未満（上限8）、終了率90%以上であることを要求します。`roulette.csv` に平均値、標準誤差、平均訪問頂点数、終了率を出力します。
この経路長は合成テストの測定値であり、実際のDXRレイ数や実行時間ではありません。

実描画は自作Preview RoomをRR有無で撮影します。最大2反射・128サンプルの組は表示領域の画素が完全一致することを要求します。
最大8反射では通常マテリアル・全体を粗い金属に上書きした2組を各512サンプルで比較します。
表示領域右側60%以降を縦横2画素間隔で検査し、RGB各平均差が±1以内、RMSEが8以内であることを要求します。
`images.json` に差分統計とPNGパスを保存します。これは表示変換後の回帰確認であり、線形放射輝度の不偏性は解析解によるGPUテストで確認します。
すべて終了コード0とPNG保存を確認し、画像も開いて見た目を確認してください。手動のUI・入力操作確認とは区別します。
